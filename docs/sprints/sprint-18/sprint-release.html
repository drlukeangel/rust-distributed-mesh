Finding (degradation, not failure)

Concurrent /api/bootstrap triggers the spawn pre-mint ghost bug at scale. Bootstrap spawns ~16 nodes at once; that concurrency races the per-spawn identity write/read, so some children boot a duplicate node_id and then fail their seed dial with invalid peer certificate: UnknownIssuer (106+ in the log) — they never join gossip and linger as ghost processes (≈6 extra procs vs visible nodes, inflating the count).

This was reproduced + root-caused this session (parallel burst of 8 → ~1 ghost), and then FIXED (commit 7aab9a2): admin-ui now passes the child's pre-minted key via RAFKA_NODE_SECRET_KEY instead of a written file, so the booted identity can't diverge from what admin-ui recorded — no file round-trip, no race. Verified: 24 concurrent spawns → 0 ghosts, 0 UnknownIssuer (was ~1/8). The soak's core criteria passed regardless; this closes the one finding.

Verdict

The mesh-v2 substrate survives the chaos battery and a 10-minute soak with flat memory and no crashes — Golden Principle #5 satisfied on the complete system. One real bootstrap-concurrency bug surfaced and is logged for a focused fix.
