## Context

RDM's node-admin learns a node is in trouble two ways: the node stops answering (silence, a failed call, an `unreached` tickle), and the deployment provider that launched the node's runtime says what it sees of that exact runtime. Today the provider can say only `Running`, `Exited` or `Unknown`. A process the operating system holds suspended (SIGSTOP) and a paused container both read `Running`, so the mesh falls back to inferring from silence, through the staleness floor and the R-FM1 hold, what the provider could have read in one call. The R-shape release cell C17 (`mock_drain_and_retire_preserve_status_and_terminal_proof`, trace `3100a0ae262f62d82e02953ef3c98d36`) showed the cost: a SIGSTOP'd compute node was held `stopping` by a status set before the node admitted anything, never inspected for 70 s, and its restart refused when it came back. The customer is whoever runs a fabric: a suspended node must be seen as suspended, a hung one as hung, a gone one as gone, with the same words whether the runtime is a pid or a container.

## Requirements

> **CANON (Luke ruling 2026-09-11):** a PRD is the GAP LIST and the BUILD LIST. Every row resolves to **HOLDS** (file:line) or **BUILD** (file:line of today, and the epic that builds it). No deferrals.

1. When a node's runtime is suspended by the operating system, the mesh-primary knows it within one recovery tick of the first unreachable command, records it, cancels any hung-runtime hold already open on that birth, and neither holds nor terminates nor replaces the node for that reason.
2. When the runtime resumes, the mesh-primary sees it on its next inspection and the pending lifecycle step resumes from its receipts; nothing reopens a terminally failed attempt on its own, and nothing sends `node.start` because the provider said `Running`.
3. The provider's answers are identical in meaning for a process and a container: `Running`, `OsStopped`, `Exited { code }`, `Unknown`. A caller reads the common result, never `/proc` or Docker.
4. An unreadable or partial inspection is `Unknown`, never exit proof; a pid gone entirely with its start identity matched stays `Exited`.
5. The provider sends no signal but the stop ladder's and the terminate's; it never continues a suspended runtime.
6. A node-admin restarted at its data dir re-adopts every runtime from the published RuntimeFacts and gets the same inspect answer, through `node.get`.
7. The existing chaos suite (`crates/rdm-test`, the R-shape release jobs) passes unchanged on these primitives: this PRD adds no chaos cell.

## Context

Node RPC standardised the transport layer (reset codes 421–424, 499; `ReplyKind`'s nine classes) and
left every domain outcome to each protocol's own reply enum, chosen handler by handler
(node-rpc.md §25: "Node RPC uses the classification for telemetry/outcome metadata only"; "every
reply byte belongs to that protocol's codec"). So `Applied`, `AlreadyApplied`, `RejectedStale`,
`RejectedNotAuthority`, `RequestNotHandled`, `already_carried`, `not_carried`, `closed` /
`unknown` / `already-closed` are per-protocol inventions that `ReplyKind` lumps into
`ProtocolRefusal` or `Success`. There is no library a handler calls to say "this already exists";
there is a convention followed by hand. The same defect as R24 (dispatch), R-MSG1 (delivery) and
i147 (gossip receive): a property decided per handler that must be decided once.

**The rule.**

Every reply of every directed Node RPC protocol classifies to exactly one of the 17 standard gRPC
codes (`rdm_core::outcome::Code`, numbers 0–16, names as gRPC spells them). RDM adds no code. RDM's
named outcome (the refusal name the pages define, the per-element lists) is the typed `detail`
beside the code, never a new number. Handlers construct replies through one library
(`reply::applied(..)`, `reply::already_applied(..)`, `reply::stale(..)`, …), never by picking an
enum variant; the protocol's classifier maps every variant to its code and is proven total (no
`Unclassified`). Clients, spans and Build receipts read the code; cells assert the detail.

**The mapping (the page text, for the typed-object contract's new `code` column).**

| gRPC code | RDM outcome |
|---|---|
| 0 `OK` | `Applied`, a read's result, a completion |
| 6 `ALREADY_EXISTS` | `AlreadyApplied`; per element: `already_carried`, `already-closed` |
| 5 `NOT_FOUND` | `SubjectUnknown`; per element: `not_carried`, an `unknown` id |
| 10 `ABORTED` | `RejectedStale` (the revision is behind: a concurrency conflict) |
| 9 `FAILED_PRECONDITION` | `RejectedInvalidTransition`, `ReceiverNotPrimary` (not the writer), a named refusal of state (`node-not-live`, `fabric-not-ready`, `rotation-in-progress`, `root-still-chained`) |
| 14 `UNAVAILABLE` | `NotReady`, `Busy`, `ConnectionsDeleting`; transport `NotSent`; a receiver proven exited or removed (detail `receiver-gone`) |
| 4 `DEADLINE_EXCEEDED` | the owner's bound lapsed, before or after the commit cut (the detail keeps not-sent versus indeterminate) |
| 2 `UNKNOWN` | `Indeterminate` other than a deadline: a lost reply, a reset after the commit cut |
| 3 `INVALID_ARGUMENT` | `Malformed` (does not decode, `UnknownVariant`) |
| 8 `RESOURCE_EXHAUSTED` | `Malformed(TooLarge)`, the admission bound |
| 15 `DATA_LOSS` | `Corrupt` |
| 12 `UNIMPLEMENTED` | `RequestNotHandled`, an `Unserved` op |
| 1 `CANCELLED` | the owner cancelled the invocation (`CallerGone`) |
| 13 `INTERNAL` | `INTERNAL_RPC_FAILURE` (the handler faulted) |
| 7 `PERMISSION_DENIED`, 16 `UNAUTHENTICATED` | reserved: never sent inside the mesh (R-RX1, node-rpc.md §14) |
| 11 `OUT_OF_RANGE` | reserved: no use |

A per-element set answer (tags, named connections) keeps its lists and carries a code per element;
the call's own code is `OK` when the call was served.
